# Submission checklist

Complete these with real evidence before submission. The repository alone is not the final assessment submission.

- [ ] Faculty approves the domain and problem statement.
- [ ] Proposal includes student and team details, responsibilities, stack, deliverables, and timeline.
- [ ] ER diagram and relational schema match the final migrations; every application table appears in the diagram.
- [ ] Show 3NF reasoning, primary/foreign keys, constraints, indexes, CRUD, joins, aggregates, view, transaction, trigger, and stored procedure.
- [ ] Demonstrate login/logout, all three roles, page and API permissions, dashboard, search, filtering, pagination, validation, and exception handling.
- [ ] Run the full application with PostgreSQL for trigger and procedure evidence.
- [ ] Perform and document a native PostgreSQL backup and restore.
- [ ] Use a private GitHub repository with team collaborators, `main` and `dev`, and at least 10 real meaningful commits.
- [ ] Keep `.env`, credentials, dumps, and keys out of GitHub.
- [ ] Build and push the Docker image to your Docker Hub account; deploy and record the live URL.
- [ ] Capture timestamped screenshots of queries, code output, UI roles, migrations, trigger/procedure, backup/restore, tests, and deployment.
- [ ] Add your actual name and registration number in code identifiers/printed output as required by the assessment. Do not use placeholders in the final submission.
- [ ] Prepare the PDF with problem statement, source code as text, input/output screenshots with timestamps, and required header details.
- [ ] Name the PDF using the assessment's `REGISTERNO_SLOT_IA9&10_Proj_NAME` pattern; upload the required PDF/DOC files to the specified course portals.

Optional marks in the brief include CI/CD, a custom domain, and one additional practice such as audit logging. CI and audit logging are implemented in this repository; a custom domain requires deployment and DNS setup.
